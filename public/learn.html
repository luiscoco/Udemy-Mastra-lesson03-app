Installing Mastra and Bootstrapping a Project

Application labWhat you will learnHow to runArchitecture & workflowCode walkthrough
01

Choose a compatible runtime

This application requires Node 24+. Check the package engines field and the selected CLI version rather than copying an old Node 18 baseline.

02

Install reproducibly

npm ci uses the committed lockfile. The project includes real Mastra dependencies and a pinned CLI for its optional Studio command.

03

Find the runtime entry

Inspect the actual src/mastra/index.ts export and registered bootstrap agent. A file that is never imported is not registration.

04

Configure the provider locally

Create your own .env file. The key must match the selected provider; diagnostics expose a boolean, never the value.

05

Check one stage at a time

Separate runtime, package, source-entry and model-access failures. A healthy page is not evidence that a provider call succeeded.

06

Launch the developer workspace

npm run studio uses the pinned Mastra CLI. Follow its printed address; this course project selects port 4203.

Check your understanding

Does a missing model key make local installation invalid?

The local lab can run without a model key. Provider access is a separate readiness check required for the live agent.

Should a new generator overwrite an existing .env file?

Preserve your existing local configuration. Copy the example only if the file is absent.

Which Studio address should a student trust?

The address printed by the running CLI, especially when a custom port is selected.

Implemented scope: Current mode reads only this project's fixed public setup files. Submitted mode checks the JSON you supply. No arbitrary filesystem paths, shell execution or provider requests are accepted by the lab.

Practical exercise

Use the broken manifest to correct one diagnostic at a time. Then compare it with the doctor's actual current-project report.
